# AgStack GeoIDs

`AgStackGeoId` computes [AgStack Asset Registry](https://github.com/agstack/asset-registry)
GeoIDs offline, in pure Kotlin Multiplatform code, bit-for-bit identical to the registry.

## How the registry computes a GeoID

1. Take the latitude/longitude **bounding box** of the geometry (a polygon's exterior ring; holes
   are ignored).
2. Cover the box with every S2 cell at a single level whose padded bounds touch it (Python
   `s2sphere.RegionCoverer` with `min_level == max_level`).
3. Encode each cell as its S2 token, keep them in ascending cell ID order, and SHA-256 their
   concatenation (no separators). The lowercase hex digest is the GeoID.

The level depends on the geometry type and on the registry's state:

| Geometry | GeoID level | Notes |
|---|---|---|
| Field (polygon) | 13 | Used when no registered field has the same level-13 hash |
| Field (polygon) | 20 | Used when the level-13 hash is taken and level-20 overlap is below the threshold (95% by default); above it the field is rejected as a duplicate |
| Point | 30 | |

Because the field level depends on what is already registered, `AgStackGeoId.forField` returns
both candidates. Treat them as provisional until the registry confirms which one was assigned.

## Usage

```kotlin
val candidates = AgStackGeoId.forField(exteriorRing) // List<GeoPoint>
candidates.primary   // level-13 GeoID
candidates.fallback  // level-20 GeoID

val pointGeoId = AgStackGeoId.forPoint(GeoPoint(latitude = 30.90706, longitude = 74.78209))

// Raw tokens, e.g. for overlap checks against the registry's s2_index__L20_list.
val tokens = AgStackGeoId.cellTokens(exteriorRing, AgStackGeoId.FIELD_FALLBACK_LEVEL)
```

## Compatibility

[`org.groundplatform.v2.core.geo.s2`](../s2/) is a minimal port of the parts of `s2sphere` the
registry exercises. It deliberately reproduces `s2sphere`'s padded cell bounds and floating-point
operation order rather than the more precise algorithms in current C++/Java S2 releases, because
any extra or missing edge cell changes the hash.

The tests check the port against:

- GeoIDs issued by the production registry (examples in the registry's README).
- Golden data generated by running the registry's own covering and hashing code
  ([`tools/geoid/generate_agstack_golden.py`](../../../../../../../../../tools/geoid/generate_agstack_golden.py)),
  covering hemispheres, the antimeridian, high latitudes, cube edges and corners, the poles, a
  ~940-acre field, and 120 seeded random fields.

Trigonometric functions can differ by one ulp between platform math libraries, so a vertex lying
within ~10⁻¹⁶ radians of a cell boundary could, in principle, yield a different covering than the
registry. The registry accepts fields up to 1,000 acres; a ~940-acre field covers about 47,500
level-20 cells.
